# MindBack（回神）设计

日期：2026-04-28

## 产品命名

- 英文名：MindBack
- 中文名：回神
- 副标题：把注意力带回今日项目

命名语义是“让跑远的注意力回来”。产品表达应偏向自我监督和温和召回，而不是监控、拦截或惩罚。

## 背景

这个工具用于支持一天只专注一个项目的 Attention 打卡计划，目标是克制 ADHD 注意力发散。它不是团队监控软件，也不是强制拦截工具，而是一个低打扰的本地监督日志工具：用户每天设定一个“今日项目”，工具在后台定期截图，用视觉模型判断当前行为是否仍然围绕今日项目，并生成可复盘的监督日志。

第一版优先做到“可信记录”和“晚上复盘”，不做实时提醒、不做强监督、不做复杂知识库。

## MVP 范围

第一版只做以下能力：

- 设置今日唯一项目。
- 在 macOS 后台定时截图。
- 每次截图后立即执行本地视觉意图识别。
- 保存清晰缩略图、识别结果、时间戳和判断原因。
- 生成当天 JSONL 日志和 Markdown 日报。
- 提供菜单栏入口和基础日志查看窗口。

第一版明确不做：

- 实时提醒或弹窗拦截。
- 多项目并行统计。
- 团队监督、远程同步或账号系统。
- 长期高分辨率原图归档。
- 完整 MineContext 式上下文数据库、向量检索或主动建议。
- 云端识别主路径。

## 产品形态

客户端是一个 macOS 桌面应用，采用菜单栏优先的使用方式。

- 首次启动显示主窗口，用于配置今日项目、模型和截图权限。
- 日常运行时常驻菜单栏。
- 菜单栏提供开始记录、停止记录、打开今日日志、打开设置、退出。
- 主窗口提供三个视图：今日状态、日志时间线、设置。

第一版不追求复杂 UI。界面应该安静、直接，避免为了监督工具本身消耗注意力。

## 技术选型

客户端框架：

- Tauri v2
- React
- Vite
- TypeScript
- Bun

后端与系统集成：

- Rust 作为 Tauri 后端。
- Rust 负责定时调度、截图采集、图片处理、本地存储和调用模型 worker。
- 截图能力优先评估 `tauri-plugin-screenshots`。
- 如果插件在 macOS 截屏权限、稳定性或清晰度上不满足要求，再实现 macOS 专用截图 bridge。

模型推理：

- Python MLX worker。
- 使用 `mlx-vlm` 运行本地视觉语言模型。
- 默认模型：`mlx-community/Qwen3-VL-8B-Instruct-4bit`。
- 备选模型：`mlx-community/gemma-4-e4b-it-4bit`。

第一版优先本地模型，不为了节省算力拆分采集频率和识别频率。云端模型只作为未来扩展，不进入 MVP 主路径。

## 为什么选择 Tauri

选择 Tauri 是为了在 Web UI 迭代效率和 macOS 桌面能力之间取得平衡。

相比 Electron，Tauri 更轻，更适合一个低打扰、长期后台运行的小工具。相比纯 SwiftUI，Tauri 能更快构建日志时间线和设置界面，也更符合 TypeScript 工具链偏好。代价是截图、Python sidecar 和打包会更工程化，需要把边界设计清楚。

## 系统架构

```text
Tauri App
├─ React UI
│  ├─ 今日项目设置
│  ├─ 开始/停止记录
│  ├─ 日志时间线
│  └─ 模型/间隔设置
├─ Rust backend
│  ├─ 定时任务
│  ├─ 截图采集
│  ├─ 图片压缩和缩略图生成
│  ├─ 本地文件存储
│  └─ 调用 MLX worker
└─ Python MLX worker
   ├─ 加载 Qwen3-VL 或 Gemma 4 模型
   ├─ 读取识别输入图
   └─ 返回结构化 JSON
```

职责边界：

- React 只负责界面展示和用户操作。
- Rust 负责所有本地系统能力和文件写入。
- Python 只负责模型推理。
- 前端不直接读写截图文件，不直接调用模型。

## 截图与识别流程

默认每 60 秒执行一次完整记录周期。

每个周期执行：

1. 截取当前屏幕。
2. 生成一张识别输入图，保留足够文字和 UI 细节。
3. 调用 MLX worker 做意图识别。
4. 生成一张日志缩略图，宽度约 960-1280px，清晰但不高分辨率。
5. 写入当天 `log.jsonl`。
6. 更新内存中的今日状态。
7. 停止记录或用户打开日报时生成 `summary.md`。

不区分“截图采集频率”和“意图识别频率”。每张截图都立即识别同一张图，避免用户难以理解，也避免缩略图识别导致细节丢失。

识别输入图和日志缩略图是两个不同产物：

- 识别输入图用于模型判断，优先保留文字细节，成功识别后删除或短期缓存。
- 日志缩略图用于复盘，长期保存，但不保留高分辨率原图。

## MineContext 调研结论

MineContext 的公开配置示例中，截图间隔为 `capture.screenshot.capture_interval: 5` 秒。其 v0.1.2 release notes 中也出现过默认截图间隔改为 15 秒的说明。

本项目不直接照搬 5-15 秒，因为目标不同：

- MineContext 是上下文挖掘和记忆工具，高频采集用于构建更完整的上下文。
- 本项目是 Attention 打卡监督工具，重点是判断一天是否围绕今日项目，不需要记录每个操作动作。

因此第一版默认 60 秒一次。这个频率在 8 小时工作日约产生 480 条记录，足够形成监督证据，同时日志噪声和本地存储压力可控。

## 模型选择

默认模型是 `mlx-community/Qwen3-VL-8B-Instruct-4bit`。

选择理由：

- 它是视觉语言模型，适合分析桌面截图。
- 对 UI、网页、代码、文档混合场景更有希望给出稳定判断。
- 对中文项目语境更适合作为默认选择。

备选模型是 `mlx-community/gemma-4-e4b-it-4bit`。

选择理由：

- 作为轻量备选，用于机器性能不足或用户更偏好 Gemma 的情况。
- 保持模型选择简单，不引入模型市场或复杂 benchmark。

第一版模型输出必须是结构化 JSON：

```json
{
  "intent": "正在编写 Attention 打卡监督工具的设计文档",
  "is_on_project": true,
  "confidence": 0.86,
  "reason": "截图显示正在编辑与今日项目相关的设计文档。",
  "visible_context": "编辑器中打开了 attention-supervisor-design.md"
}
```

字段说明：

- `intent`：模型判断当前行为的简短描述。
- `is_on_project`：是否符合今日项目。
- `confidence`：0 到 1 的置信度。
- `reason`：一句话说明判断依据。
- `visible_context`：截图中可见的关键上下文。

## 数据存储

本地数据放在 macOS Application Support 目录：

```text
~/Library/Application Support/MindBack/
└─ days/
   └─ YYYY-MM-DD/
      ├─ log.jsonl
      ├─ summary.md
      └─ thumbs/
         ├─ 09-30-00.jpg
         └─ 09-31-00.jpg
```

`log.jsonl` 每行是一条记录：

```json
{
  "timestamp": "2026-04-28T09:30:00+08:00",
  "project": "Attention 打卡监督工具",
  "screenshot_thumb": "thumbs/09-30-00.jpg",
  "model": "mlx-community/Qwen3-VL-8B-Instruct-4bit",
  "intent": "正在讨论客户端框架选型",
  "is_on_project": true,
  "confidence": 0.82,
  "reason": "可见内容是 Tauri 与 MLX 架构讨论。",
  "visible_context": "浏览器或编辑器中显示 Tauri、React、MLX 等内容",
  "error": null
}
```

错误事件也写入同一个 JSONL，避免静默丢记录。

## Markdown 日报

日报用于晚上复盘，内容包含：

- 今日项目。
- 记录开始和结束时间。
- 总记录数。
- 符合项目的记录数和比例。
- 不符合项目或不确定的时间段。
- 时间线摘要。
- 缩略图引用。

日报不应该过度解释用户行为，只提供监督证据和模型判断，避免产生额外心理负担。

## 错误处理

屏幕录制权限不足：

- 主窗口显示授权指引。
- 记录按钮不可启动或启动后立即失败。
- 日志写入权限错误事件。

截图失败：

- 写入 `capture_error`。
- 不中断后续周期。

MLX worker 不可用：

- 写入 `worker_unavailable`。
- UI 显示模型未就绪。

单次识别超时：

- 保存缩略图。
- 写入 `timeout`。
- 后续周期继续执行。

模型输出不是合法 JSON：

- 写入 `parse_error`。
- 保存有限长度的原始输出片段，便于调试。

磁盘写入失败：

- UI 显示错误状态。
- 暂停记录，避免继续产生不可追踪的状态。

## 设置项

第一版设置项保持少量明确：

- 今日项目名称。
- 今日项目描述。
- 截图间隔：默认 60 秒，可选 30、60、120、300 秒。
- 模型选择：Qwen3-VL 或 Gemma 4。
- 日志目录：默认 Application Support，可打开目录。

开机启动不进入第一版设置，作为后续扩展处理。

## 验证标准

第一版完成时需要验证：

- 无屏幕录制权限时能正确提示。
- 授权后可以开始记录。
- 停止记录后不会继续截图。
- 60 秒周期能生成截图、缩略图和 JSONL 记录。
- MLX worker 能使用默认模型识别至少一张真实桌面截图。
- Gemma 4 备选模型至少能完成一次识别 smoke test。
- 日志时间线能展示当天记录和缩略图。
- Markdown 日报能从 JSONL 生成，且缩略图链接有效。

## 后续扩展

后续可以考虑：

- 轻提醒：连续多次偏离时提醒一次。
- 本地模型健康检查和模型下载引导。
- 更好的日报聚合，把连续同类记录合并成时间段。
- 云端视觉模型作为显式 opt-in 兜底。
- 隐私模式：对缩略图局部打码或只保存识别结果。
- 完整打包分发，包括 Python worker 和依赖环境。
